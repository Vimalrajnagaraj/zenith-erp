Inventory dashboard: functional bug report

Audit date: 6 October 2026 · Baseline: PR #17, commit f4422ad · Fix branch: codex/inventory-dashboard-functional-fixes

This report covers the dashboard itself, its filters, drilldowns, customization controls, chart interactions, and Inventory navigation entry points. Testing used the local Docker demo with repository source installed; the visual-only sample override was removed. No production system was accessed.

Evidence: browser clicks on /apps and /qapps; source inspection; read-only HTTP regression checks; local database checks for preference persistence. Synthetic AUDIT_INV_* records belong only to LOCAL_ERP_ORG. They test presentation and filtering, and are not a balanced business inventory history.

Bug register

INV-F01 — Add New opens an invalid edit page · High

Reproduce: click Add New on the baseline dashboard. Actual: EditProduct opens without productId and displays “Required parameter missing (productId).” Expected: reach a valid product creation entry point.

Cause/fix: the action used the required-ID edit screen. It now opens Product Catalog, where the existing New Product dialog creates a product. Verification: Add New → New Product → creation form tested on both surfaces; no product was submitted.

INV-F02 — Header intercepts Inventory tab clicks · High

Reproduce: use the /apps dashboard at the audit window width (1265px), with its long organization header; click Products. Actual: navigation does not happen. The header container grows to 99.2px and covers the tab hit target. Expected: the tab receives the click.

Cause/fix: floated header controls wrapped above the tabs. Dashboard-scoped desktop flex layout keeps the header in one row with a shrinking search field. Verification: header height becomes 50px; the hit target is the anchor; all ten sibling Inventory tabs navigate successfully.

INV-F03 — All time silently excludes older movements · Medium

Reproduce: have a January 2025 movement and select All time in October 2026. Actual: the baseline displays “last 6 months” and excludes January. Expected: include the full available history.

Cause/fix: an empty range defaulted to six months. It now starts at the earliest scoped ledger/activity timestamp, uses calendar-day boundaries, and labels the range All time. Monthly buckets start on day 1 to avoid skipping months near month-end. Verification: fixture all-time inflow is 80; October-only inflow is 5. Weekly KPIs remain rolling/current as labeled.

INV-F04 — Malformed date parameters can fail rendering · Medium

Reproduce: open the dashboard with ?dashDate=invalid on the baseline. Actual: unchecked Timestamp.valueOf input can throw instead of rendering the page. This cause was confirmed in source. Expected: validation feedback and a usable dashboard.

Fix: strict LocalDate parsing, safe fallback, and an inline alert. End-only input becomes a single-day range; reversed valid endpoints continue to normalize. Verification: invalid input returns HTTP 200 with a visible validation message; reversed October dates return the correct normalized range.

INV-F05 — View All links do not show the associated records · Medium

Reproduce: click View All in Recent Transactions, Low Stock Alerts, or Products Needing Details. Actual: the first two open general Stock Levels; the third opens the entire catalog. The selected dashboard warehouse is lost on Stock Levels. Expected: inspect the associated records in scope.

Fix: scoped in-page drilldowns: ledger pages of 50 records, the complete tracked low-stock list, and products with missing details linked to their edit screens. Product links are also available in transaction and alert rows. The View Stock Levels quick action now passes the selected facility. Verification: transaction pages contain 50 + 7 rows with Next/Previous controls; affected product links open valid edit pages; warehouse A remains in the quick-action URL.

INV-F06 — Low-stock alerts include untracked products · Medium

Reproduce: create one tracked product plus an untracked product with a reorder point and no assets. Actual: the baseline checks whether any tracked product exists, then iterates the entire ProductStockView. Source confirms untracked products can count as zero-stock alerts. Expected: only inventory-tracked products trigger these alerts.

Fix: restrict the view to the organization's tracked product IDs. Verification: Warehouse A shows the tracked product at 5 against reorder point 10; the untracked fixture is excluded.

INV-F07 — Zero-quantity ledger entries hide real recent movements · Medium

Reproduce: add at least 50 newer zero-quantity AssetDetail entries before older real movements. Actual: the baseline limits to 50 rows before skipping zero changes, so real movements disappear. Source confirms the limit/filter ordering. Expected: recent transactions show real quantity changes.

Fix: exclude zero quantity changes in the database query before ordering and pagination; use assetDetailId as a stable tie-breaker. Verification: 60 newer zero changes do not hide the 8-row summary or the 57 real movements in the expanded list.

INV-F08 — Customization does not affect the new cards and loses context · Medium

Reproduce: open additional insights → gear → deselect Stock Movements → Save Layout, with a warehouse/date filter selected. Actual: the new chart ignores saved visibility flags; the settings section reloads collapsed; save/reset/custom date forms omit warehouse parameters. These mismatches were confirmed in source.

Fix: the new KPI, warehouse, movement, recent, and low-stock sections respect the existing flags; the settings disclosure opens when requested; save/reset/close and custom-date controls preserve warehouse/date context. Reordering text now clearly refers to additional insights. Verification: saving hides the new chart, retains Warehouse A and October dates, and leaves settings visible; Reset restores the chart.

INV-F09 — One-third additional-widget width is not saved · Low

Reproduce: choose a one-third width in the additional-insights layout and reload. Actual: the client supports third, but the server accepts only half and drops third. Expected: retain the selected supported width.

Fix: allow both half and third in the existing validated size list. Verification: tested by posting the layout transition and checking the saved preference; drag/resize is an additional-insights feature, not a rearrangement of the fixed reference dashboard.

Repeatable regression check

On the existing local Docker demo, install docs/qa/inventory-dashboard-functional-fixtures.sql using psql inside zenith-erp-db-1. Restart Moqui after direct SQL fixture loading so cached catalog queries refresh. Then run node docs/qa/inventory-dashboard-functional-check.mjs. The script is read-only and refuses non-local hostnames. Credentials can be provided through SMOKE_USER and SMOKE_PASS; defaults match the existing demo.

Limits and review

These checks are evidence for the listed defects, not a guarantee that every possible production case passes. Testing used one administrator, two local warehouses, and synthetic records. Restricted-role behavior, concurrent users, global shop-switch integration, and production-scale volumes still need owner/UAT validation. Transfers, receipts, adjustments, exports, forecasting, and product writes beyond dashboard entry points were not performed.

PR #17 is still open at audit time. The functional-fix branch depends on it; merge the UI PR first, then review/retarget the functional PR against master. Deployment is required after merge.
