# Vendor-bill disposable acceptance

This suite exercises the actual routed Purchase invoice screens in both `/apps` and `/qapps`, plus their typed services. It never accesses production. Production observations were limited to navigation, form structure and layout, without submitting business changes.

Start an isolated Moqui runtime at `127.0.0.1:18085` with an H2 memory database named `purchase-pricing-qa` and TCP port `19097`. Enable `purchase.pricing.qa.disposable=true`; load only clean tracked seed/demo data. Copy `fixture.xml` to the Purchase component root as `VendorBillQaFixture.xml` and `qa-screen.xml` to the Pricing screen directory as `VendorBillQaAcceptance.xml`. These QA files belong outside deployed component sources and must never be installed on a production runtime. The helper refuses initialization without the disposable property and platform ADMIN; service probes require the synthetic QA account and an explicit operation allowlist.

Set `BILL_QA_RUNTIME`, `BILL_QA_JAVA` and `BILL_QA_OUT`, then run `node verify.cjs` with Playwright available. The current Windows harness uses installed Chrome and JDK 21. It compiles `VendorBillDbProbe.java`, a SELECT-only independent database probe. The local framework rebuild is not byte-identical to production; use the trusted master workflow against the exact candidate SHA for canonical staging verification as well.

Positive persisted writes accompany rejected-input checks. Coverage includes both creation transitions, normal/reverse-charge/composition lines, full discounts, approved seed cess, stored unrounded tax-inclusive grand and separate round-off, protected header fields, finalized/foreign/missing records, CSRF, filtered CSV links and zero-row headers, charged-tax/GSTR report compatibility, actual page content and responsive layout. Synthetic fixtures reuse SAC `998314` from tracked Subscriptions seed, state `33`, and approved `GST_18`/`GST_28_CESS_5` metadata. Arithmetic values are mechanical test inputs; no legal registrations, stock assumptions or tax defaults are fabricated.

Before cleanup the suite snapshots issued/foreign/Sales controls and all invoices outside fixture ownership. Cleanup first resolves all invoice IDs owned by the exact synthetic parties, then deletes their exact tax-line and invoice-item children and headers. User-group memberships use their actual stored composite keys, because seed timestamps use the initializing user's timezone. Remaining fixture entities are deleted by their declared primary keys. Independent SQL verifies zero residue across business, configuration and auxiliary/security fixture tables, generated children removed and outside invoices unchanged. Destroy the disposable JVM after any failed run; do not continue using partial fixture state.

An exact disposable buyer configuration is temporarily switched to the composition scheme and restored. Creation stores ITC No, both routed metadata transitions reject a forged ITC Yes, and the normal supplier's charged GST remains payable. This reads the configured scheme without inventing registrations or rates; the restriction follows [CGST Section 10(4)](https://taxinformation.cbic.gov.in/content-page/explore-act/1000279/1000001). The bill services validate the stored choice; reconciliation/reporting eligibility is a separate audit. Report compatibility assertions here cover ordinary eligible bills and charged tax arithmetic.

Latest local run: 350/350 checks passed, including actual browser form creation on both surfaces, 32 viewport checks, Quasar header overlap/navigation checks, readable tax-summary contrast, aligned bill icons and exact cleanup. GitHub checks and the owner deployment gate remain separate requirements.
