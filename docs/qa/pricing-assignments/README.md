# Pricing assignment service verification

Disposable loopback runtime only. Use the same runtime isolation and canonical staging overrides described in the sibling Dashboard README. Copy `fixture.xml` as `runtime/component/zenith-erp-pricing/PricingAssignmentQaFixture.xml`, and `qa-screen.xml` into the pricing screen directory as `PricingAssignmentQaAcceptance.xml`. Set `ASSIGNMENT_QA_RUNTIME`, `ASSIGNMENT_QA_JAVA` and `ASSIGNMENT_QA_OUT`; run `node docs/qa/pricing-assignments/verify.cjs`.

The assignment service has no advertised standalone UI; this suite calls the real authenticated service through a disposable-only, POST/CSRF-protected helper. Baseline reproduced 11 failed assignment checks before a viewer-token harness timeout. The corrected final run completes 62 checks with no failures or errors, including customer/group positive controls, inactive planned list configuration, canonical derived ownership, exact integer priority (3.0 accepted; 1.5 and overflow denied), invalid/ordered dates, foreign/missing/disabled/wrong-role references, mutually exclusive targets, raw no-org, changed active organization, denied financial viewer and missing CSRF. It preserves eight independent business-table snapshots and cleans captured exact generated IDs and fixture/auxiliary keys; SELECT-only SQL confirms zero residue across 11 tables and unchanged invoices.

No effective prices, products, tax defaults, stock or legal identities are seeded. The public demo password is used only for disposable users; deployed credentials are absent. This does not replace trusted staging or the owner MARUTHI no-op database evidence required by the SOP.
